# 声解析アプリ(声質・声タイプ診断)設計書

作成日: 2026-11-09 / 状態: レビュー待ち

## 1. 目的と範囲

**目的**: ブラウザ(スマホ中心)でマイク録音すると、声質と声タイプを診断し、グラフと解説付きのフィードバックを表示するアプリ。

**ロールモデル**: QTV Academy(https://system.qtv-academy.jp/)の声解析システム「クォンタムヴォイス」。
参考にした点は、Web上で波形を録音すること、虹色の棒グラフと円グラフで周波数の配分を示す結果画面、アドバイスの提示、白地に赤のアクセントの見た目。
同サイトはこのセッションのネットワークから開けず、ユーザーが共有したスクリーンショット1枚のみを参照した。独自理論(色や帯の意味づけ)は再現しない。

**v1の範囲**: 診断のみ。ログイン、履歴保存、講師用の管理画面、講師によるフィードバック入力は作らない。

**診断の位置づけ**: 一般的な音声科学の範囲で作る。結果画面に「一般的な声の傾向の目安であり、QTV Academy の理論の再現や医療診断ではない」と明記する。

**前提(未確認)**: 新規プロジェクトで、対象はスマホブラウザ中心。プロの声診断士による内容確認は受けられない。

## 2. 画面

ログインなしで、1ページ内で3画面を切り替える。見た目は白地に赤のアクセント(`#c8213c` 前後)、明朝系の見出し、虹色のグラフ。スマホ縦画面を優先する。

1. **スタート**: アプリの説明、「この診断でわかること」、録音のコツ(静かな場所、マイクから約20cm)、マイク使用の案内、「声解析する」ボタン。
2. **録音**: 読み上げ文の表示。母音「あー」を約5秒、文の読み上げを約10秒の順に録音する。録音中は波形をリアルタイムで表示する。
3. **結果**:
   - 上部に「あなたの声は〇〇タイプです」の一言説明
   - 虹色の棒グラフ(12帯の強さ、0〜60)と虹色の円グラフ(12帯の割合 %)
   - グラフの読み方の案内
   - 12帯の凡例(タップで、色と、その帯が強いときの声の特徴を一行表示)
   - フィードバック(第5節)
   - 「もう一度録音する」ボタン

## 3. 測定項目

| 項目 | 指標 | 使い道 |
|---|---|---|
| 声の高さ | F0(YIN で検出)の平均と変動幅(半音単位) | 高さの表示、抑揚(単調さ) |
| 明るさ | スペクトル重心、高域/低域のエネルギー比 | 声タイプの軸1 |
| 澄み具合 | HNR、CPPS | 声タイプの軸2、息漏れ |
| 声量 | RMS(dBFS) | 声の張り、小さすぎる声 |
| 安定性 | 母音の F0 と RMS のゆらぎ | 息の支え |
| 話す速さ | 発話区間の割合 | 間の取り方 |
| 12帯の配分 | 100 Hz〜8 kHz を対数で12分割 | 棒グラフと円グラフ |

- 12帯の境界(Hz): 100・144・208・299・431・621・895・1290・1859・2679・3860・5563・8000。低域の赤から高域の紫の順に虹色を割り当てる。
- 円グラフは各帯のエネルギー割合(%)。棒グラフは各帯の強さを 0〜60 に正規化した値。
- 声の高さ(F0)は声タイプの判定に使わない。高さは「〇〇 Hz(音名 〇〇)」と事実として表示する。性別の入力は求めない。
- 録音の2種類(母音の伸ばしと文の読み上げ)を併用する。伸ばし母音だけでは普段の声質を測れないため。
- マイクのエコーキャンセル、ノイズ抑制、自動ゲインは切る。

## 4. 声タイプ(4タイプ、2軸)

軸1は「明るさ」、軸2は「澄み具合」。

| | 澄んでいる | やわらかい(息混じり) |
|---|---|---|
| **明るい** | 透明感タイプ | ふんわり軽やかタイプ |
| **落ち着いている** | 深み・安定タイプ | やわらか包容タイプ |

境界値は文献と一般的な目安による**仮置き**で、`diagnosis/config.ts` に分離する。サンプル録音を集めて調整する前提とする。

## 5. フィードバック

タイプごとに文言を用意し、次の構成で組み立てる。

1. 声の傾向: 一言の説明と、聞き手に与えやすい印象
2. 強み: 強い帯や指標から自動生成
3. 伸ばすポイント: 弱い指標から最大2つ
4. 練習メニュー: 3つ程度(ハミングで響きを前に集める、「す―」で息を長く一定に出す、抑揚をつけた音読 など)
5. 注意書き: 傾向であり断定ではないこと、喉の不調が続くときは専門医へ

表現は「〇〇な傾向があります」とし、断定や病気の診断に当たる言い方は避ける。

## 6. 技術構成

- TypeScript と Vite の静的サイト。フレームワークは使わない。
- 音声処理(YIN、FFT、HNR、CPPS)は自前の TypeScript で書く。ブラウザ内で完結し、音声は外部に送らない。
- グラフは SVG で自作する(チャートライブラリは使わない)。
- テストは Vitest。画面の通し確認は Playwright。
- マイクの利用に HTTPS が必要なため、公開は静的ホスティング(GitHub Pages など)を想定する。

### データの流れ

マイク録音 → 生の波形(Float32)→ 録音品質チェック → 特徴量の計算 → タイプ判定 → フィードバック文の組み立て → 結果表示。

録音終了後にバッファ全体をまとめて解析する。リアルタイムなのは、録音中の波形表示のみ。

### 配置とファイル構成

このセッションで使えるリポジトリは `spica-images` のみのため、`voice-analyzer/` フォルダとして置く。Instagram 画像の `jp/` とは独立しており、後で別リポジトリへ移せる。

```
voice-analyzer/
  src/
    audio/capture.ts       マイク取得(加工オフの設定)、録音バッファ
    dsp/pitch.ts           YIN による F0 検出
    dsp/spectrum.ts        FFT、12帯のエネルギー集計
    dsp/quality.ts         HNR、CPPS、音量、ゆらぎ
    dsp/features.ts        上記をまとめて特徴量にする
    diagnosis/gate.ts      録音品質チェック(ノイズ、小音量、音割れ)
    diagnosis/classify.ts  2軸から4タイプを判定
    diagnosis/feedback.ts  フィードバック文の組み立て
    diagnosis/config.ts    境界値、帯の定義、文言
    ui/                    3画面と SVG グラフ
  tests/                   音声処理と判定の単体テスト
```

`dsp/` と `diagnosis/` は画面から独立させ、後で解析部分だけをサーバー方式に差し替えられるようにする。

## 7. エラー処理

- マイク許可の拒否、マイクが無い、HTTPS でない場合は、理由と対処を画面に表示する。
- サンプルレートは端末の実測値を使う。iOS Safari では録音開始にユーザー操作が必要。
- 無音や F0 が検出できない場合は、診断せずに録り直しを案内する。
- ノイズが大きい、音量不足、音割れの場合も、診断せずに録り直しを案内する。

## 8. テスト方針

- **音声処理の単体テスト**: 既知の合成音で検証する。200 Hz の正弦波なら F0 が約 200 Hz、倍音とノイズを混ぜた音なら HNR が想定どおり変わる、など。
- **判定のテスト**: 合成した特徴量から、各タイプに期待どおり分類されることを確認する。
- **画面の通し確認**: Playwright と Chromium の疑似マイク機能に WAV を流し、録音から結果表示までを確認する。
- **実機確認**: iPhone Safari と Android Chrome で、手動チェックリストに沿って確認する。

## 9. 既知の限界

- 声タイプの境界値と解説文は、正解データのない仮置きである。
- 端末とマイクの違い、録音環境で数値はぶれる。ジッター、シマー、HNR は録音環境が悪いと信頼性が下がり、声量にも左右される。
- 自動テストでは、実際の声に対する判定の妥当性は保証できない。サンプル録音を集めたうえで、境界値を調整する。
- QTV Academy の独自理論と、プロの声解析士による内容確認は含まない。
