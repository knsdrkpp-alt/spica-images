# 声解析アプリ(声のタイプチェック)設計書

作成日: 2026-11-09 / 改訂: 2026-11-09(ディープリサーチ反映) / 状態: レビュー待ち

根拠調査: `reports/声診断アプリ設計の根拠調査.md`(統合レポート)、`research_notes/声診断アプリ設計の根拠調査/`(5本のノート)

## 0. 改訂の要点(初版からの変更)

ディープリサーチの結果、初版から次の点を変更した。各変更には根拠の区分と確信度を付けた(レポート参照)。

| # | 変更 | 理由(要約) |
|---|---|---|
| 1 | 名称を「診断」から「声のタイプチェック」(仮称)に。結果は「今日の声の傾向」「〇〇タイプの傾向です」 | 薬機法上の該当性は表示や広告から判断される。断定ラベルは日内変動と聴取者差からも支えられない |
| 2 | 澄み具合の主指標を HNR から **CPPS** に。HNR は補助 | 気息性との相関が最も頑健(メタ分析 r≈.64〜.66)。HNR は手法依存が大きい |
| 3 | ジッター、シマー、絶対 SPL、絶対バンド値は**表示しない** | 機種差、ノイズ、残響、AGC に弱い |
| 4 | 絶対値の閾値をやめ、**性別内パーセンタイルと自己ベースライン**で運用 | CPPS の閾値は課題、ソフト、言語で大きく変わり、日本語の規範値は未取得 |
| 5 | 単回判定をやめ、**最大3セットの中央値**と**中間タイプ** | 日内変動の報告あり。境界付近は再測定でタイプが変わりうる |
| 6 | 声タイプの「聞き手に与えやすい印象」の説明をやめ、音響的な傾向の記述に限定 | 社会的印象との関係は弱く、研究間で不一致 |
| 7 | マイクの加工オフは `ideal` 指定と `getSettings()` による事後検証に | iOS Safari では要求しても切れていない報告がある |
| 8 | 受診案内を、測定値に連動しない固定フッターに | 疾患判定とみなされるリスクの回避(要弁護士確認) |
| 9 | 内部は連続プロファイルで保持し、表示を2軸4タイプのラベルにする | 商用・教育の分類は高さ、クリア〜ハスキー、明るさ、力強さに収斂 |

## 1. 目的と範囲

**目的**: ブラウザ(スマホ中心)でマイク録音すると、声の特徴を測り、声タイプの傾向をグラフと解説付きで表示するセルフチェック兼練習支援のアプリ。

**位置づけ**: 医療や診断のツールではない。疾患名、診断、検査、スクリーニング、リスク、予防、受診要否の判定に当たる語と機能を、画面、LP、規約、ストア説明のすべてで使わない。

**ロールモデル**: QTV Academy(https://system.qtv-academy.jp/)の声解析システム「クォンタムヴォイス」。参考にしたのは、Web上で録音すること、虹色の棒グラフと円グラフの結果画面、アドバイス、白地に赤のアクセントの見た目。同サイトはこのセッションのネットワークから開けず、ユーザーが共有したスクリーンショット1枚のみを参照した。独自理論(色や帯の意味づけ)は再現しない。

**v1の範囲**: 結果表示のみ。ログイン、サーバー保存、講師用の管理画面、講師によるフィードバック入力は作らない。

**対象外・精度低下**: 吃音、構音障害、変声期、方言、非母語話者、小児では精度が下がる。スタート画面で事前に明記する。提供地域は日本に限定し、規約に明記する(要弁護士確認)。

## 2. 画面と流れ

ログインなしで、1ページ内で画面を切り替える。見た目は白地に赤のアクセント(`#c8213c` 前後)、明朝系の見出し、虹色のグラフ。スマホ縦画面を優先する。

1. **スタート**: 説明、「この診断でわかること」に代わる「このチェックでわかること」、録音のコツ(静かな場所、マイクから約15〜30 cm)、対象外の案内、プライバシーの案内(音声は端末の外に送らない)、「声を録音する」ボタン。
2. **録音**: 1セット = 母音「あー」約5秒 + 文の読み上げ約10秒。録音中は波形をリアルタイムで表示する。録音の前にマイク許可の事前説明を出し、録音中は表示を出す。
3. **結果**:
   - 上部に「今回の録音では〇〇タイプの傾向です」の一言説明。1セットのときは「参考(1回)」と明記する
   - 虹色の棒グラフ(12帯の相対的な強さ)と円グラフ(12帯の割合 %)
   - グラフの読み方の案内
   - 12帯の凡例(タップで、色、周波数帯、一般的な傾向の目安を一行表示。音響的な裏づけは弱い目安であることを注記)
   - フィードバック(第5節)
   - 「もう1セット録音する」ボタン(最大3セット。2セット目以降で中央値に切り替わり、「より安定した結果」と表示)
   - 固定フッター: 声に関する注意と受診の案内(第5節)

## 3. 測定項目

母音と文は別々に集計する(課題でF0とCPPSの挙動が違うため)。

| 項目 | 指標 | 使い道 | 表示 |
|---|---|---|---|
| 声の高さ | F0の中央値、変動は半音の5〜95パーセンタイル範囲 | 高さの事実表示(Hzと音名)、抑揚 | 表示する |
| 澄み具合(主) | CPPS(文は無音区間を除去して計算。母音は補助) | 軸2 | タイプと説明にのみ使う |
| 澄み具合(補助) | HNR、H1-H2 | 補助。単独では軸に使わない | 参考扱いか非表示 |
| 明るさ | alpha ratio または LTAS の高域/低域比(主)、F0補正した重心(補助)。性別内でz化 | 軸1 | タイプと説明にのみ使う |
| 力強さ | 発話内の相対的な声量の変動など(絶対音量は使わない) | 内部プロファイルの3次元目候補 | v1では内部のみ |
| 安定性 | 母音のF0とレベルのゆらぎ | 息の支え | 表示する(説明付き) |
| 話す速さ | 読み上げ文のモーラ数から articulation rate(ポーズ除外)と speaking rate を算出。前者を主表示 | 間の取り方 | 本人比で表現 |
| 12帯の配分 | 100 Hz〜8 kHz を対数で12分割した相対値 | 棒グラフと円グラフ | 全帯域比の相対値のみ |

- 12帯の境界(Hz): 100・144・208・299・431・621・895・1290・1859・2679・3860・5563・8000。低域の赤から高域の紫の順に虹色を割り当てる。12帯LTASの妥当性を検証した研究は見つかっていない。設計独自の可視化として扱い、端末間の絶対比較や基準値との比較はしない。
- **表示しない指標**: ジッター、シマー、NHR、絶対SPL、CPP由来のF0、絶対バンド値。内部の品質ゲートでのみ使うことがある。
- F0は声タイプの判定に使わない。明るさ軸へのF0の混入は、性別内z化とF0補正重心で緩和する。
- 話す速さ、声量、F0の変更を勧めるときは、本人比の段階的な目標にとどめる(第5節)。

## 4. 声タイプ

### 内部プロファイルと表示
内部では、明るさ、澄み具合、高さ、抑揚、力強さの連続値を保持する。表示は、明るさと澄み具合の2軸による4タイプのラベルとする。

| | 澄んでいる | やわらかい(息混じり) |
|---|---|---|
| **明るい** | 透明感タイプ | ふんわり軽やかタイプ |
| **落ち着いている** | 深み・安定タイプ | やわらか包容タイプ |

タイプの軸とラベルは、音響特徴から導いた経験的な分類であり、知覚実験での検証はされていない。結果画面に「目安」と明記する。

### 境界の決め方
- 絶対値ではなく、**性別別の分布に対するパーセンタイル**で境界を決める。45〜55パーセンタイルを「中間」とし、隣接タイプの混合として表示する。
- 性別の入力は任意(自己申告)にする。未入力のときは全体分布と自己比較を使う。男性的/女性的の判定は出さない。
- パーセンタイル表は、β運用で集めたデータ(目安として性別ごとに数百件以上)から作る。それまでの境界は、自前実装の出力に基づく**仮置き**で、結果画面に「仮の基準」と明記する。
- 境界値とパーセンタイル表は `diagnosis/config.ts` に分離する。

### 判定の単位
- 最大3セットの中央値で判定する。2セットで境界を跨ぐ場合は中間タイプにする。
- ラベルは「今日の傾向」とし、固定のタイプとして扱わない。

## 5. フィードバック

タイプごとの文言を用意し、次の構成で組み立てる。

1. **声の傾向**: 音響的な特徴の記述に限る。「聞き手に与えやすい印象」「性格や能力が分かる」といった断定はしない。
2. **強み**: 強い帯や指標から自動生成する。
3. **伸ばすポイント**: 最大2つ。数値は単独で見せず、本人の推移と「だいたい」の幅で示す。
4. **練習メニュー**: ウォームアップ(ハミングまたはストロー発声1〜2分)、優先課題1〜2種(各2〜3分)、普段の声への転移1分。合計5〜10分、週3〜5日、2〜4週で再測定。効果は「楽に出せるようになる可能性」と表現し、治る、良くなると断定しない。
5. **段階目標(暫定)**: 抑揚は本人比で+0.5〜1半音、F0の変更は1回1〜2半音以内、声量は数dB以内、話速は10〜20%以内。出典のない臨床慣習の暫定値。
6. **中止の案内**: 痛み、疲れ、かすれの悪化があれば練習をやめる文言を毎回表示する。声を張る方向の練習は勧めない。

**表現ルール**:
- 使う: 「今回の録音では〜の傾向」「〜かもしれません」
- 使わない: 異常、正常、リスク、疑い、悪化、改善します、高精度
- 赤や警告色を、結果の良し悪しの表現に使わない

**固定フッター**(測定値に連動させない): 「声のかすれが長く続く(目安として4週間以上)、息苦しさや吸うときの音、痛み、痰に血が混じる、飲み込みにくさ、首のしこりがあるときは、医療機関(耳鼻咽喉科)に相談してください。このアプリは医療や診断のためのものではありません。」4週間の目安は米国耳鼻咽喉科頭頸部外科学会(2018年)に基づく。日本の学会基準は未確認で、要確認。

## 6. 技術構成

- TypeScript と Vite の静的サイト。フレームワークは使わない。
- 音声処理は自前の TypeScript で、Praat 互換の出力を目標にする。ブラウザ内で完結し、音声、特徴量、スコアを外部に送らない。
- グラフは SVG で自作する。
- テストは Vitest、画面の通し確認は Playwright。
- マイクの利用に HTTPS が必要なため、公開は静的ホスティング(GitHub Pages など)を想定する。

### 録音と解析
- 録音は **AudioWorklet で Float32 PCM を蓄積**する。ScriptProcessor は非推奨のフォールバック。MediaRecorder は圧縮でスペクトル指標が歪むため、解析に使わない。
- サンプルレートは `AudioContext.sampleRate` の実測値を使う(iOS では44.1 kHzを要求しても48 kHzになる例がある)。最低16 kHz、48 kHz を優先する。
- マイク設定は、`echoCancellation`、`noiseSuppression`、`autoGainControl` を `ideal` で false に要求し、`track.getSettings()` で実際の値を検証する。切れていなければ結果に「処理あり・信頼度低」のフラグを付ける。iOS Safari では `exact: false` でエラーになりうるため例外処理を入れる。
- 画面オフやタブ切替で AudioContext が "interrupted" になるため、`resume()` の処理と、録音の中断検知を入れる。
- F0は YIN(しきい値0.10〜0.15)に、メディアン平滑とオクターブジャンプの棄却を追加する。有声判定は正規化自己相関で行う。探索範囲は約60〜500 Hz。
- CPPS は Praat の `To PowerCepstrogram` と `Get CPPS` に準拠して実装する(Hillenbrand 方式のトレンド)。HNR は Praat の `To Harmonicity (cc)` 相当。具体的なパラメータは、実装時に Praat のマニュアルで確認して確定する。
- 12帯は、有声フレームの長時間平均スペクトルから、全帯域比の相対値で算出する。

### 配置とファイル構成

このセッションで使えるリポジトリは `spica-images` のみのため、`voice-analyzer/` フォルダとして置く。`jp/` とは独立しており、後で別リポジトリへ移せる。

```
voice-analyzer/
  src/
    audio/capture.ts       マイク取得(ideal指定と事後検証)、AudioWorklet録音
    dsp/pitch.ts           YIN、後処理、有声判定
    dsp/spectrum.ts        FFT、12帯の相対値、alpha ratio、重心
    dsp/quality.ts         CPPS、HNR、H1-H2、ゆらぎ
    dsp/features.ts        課題ごとに特徴量をまとめる
    diagnosis/gate.ts      録音品質ゲート
    diagnosis/profile.ts   連続プロファイル(性別内z化、パーセンタイル)
    diagnosis/classify.ts  2軸から4タイプと中間タイプを判定、3セットの中央値
    diagnosis/feedback.ts  フィードバック文の組み立て(表現ルールの検査を含む)
    diagnosis/config.ts    境界値、パーセンタイル表、帯の定義、文言
    ui/                    画面と SVG グラフ
  tests/                   単体テスト、Parselmouth との回帰テスト用データ
```

`dsp/` と `diagnosis/` は画面から独立させ、後で解析部分だけをサーバー方式に差し替えられるようにする。

## 7. 録音品質ゲート(暫定値)

以下はすべて**出典のない暫定値**で、複数機種の実機データで調整する。

| 項目 | 暫定値 | 確信度 |
|---|---|---|
| SNR(録音前後の無音区間と発声区間の比) | 30 dB 以上で通常、20〜30 dB で警告、20 dB 未満で再録音(SNR の計算では両区間から直流分と 80 Hz 未満を除き、発声区間は最大フレームから 20 dB 以内のフレームで測る)。ノイズフロアは -50 dBFS 以下 | 低〜中 |
| クリッピング | 絶対値0.99以上が全体の0.1%超、または連続3サンプル以上で再録音 | 中 |
| 入力レベル | 発声区間のピーク -20〜-3 dBFS を目標。-30 dBFS 未満は「小さい/遠い」と警告 | 低〜中 |
| 持続母音 | 安定部3秒以上(先頭と末尾を各0.5〜1秒除外)。中間2秒で F0 の SD が約50 cent 以内、レベル変動 ±6 dB 以内 | 低〜中 |
| 文の読み上げ | ポーズ除去後の有声時間と割合を確認 | 中 |
| 距離 | 口からマイクまで15〜30 cm をUIで案内 | 中 |
| サンプリング | 実測値を使う。Bluetooth マイクの帯域制限(4 kHz 以上のエネルギーの有無)を検査 | 中 |
| 端末処理 | `getSettings()` の実際の値を取得し、有効なら信頼度フラグ | 中 |

## 8. エラー処理

- マイク許可の拒否、マイクが無い、HTTPS でない場合は、理由と対処を画面に表示する。拒否されても、説明画面は使える。
- 無音、F0が検出できない、ノイズが大きい、音量不足、音割れの場合は、結果を出さずに録り直しを案内する。
- iOS Safari の制約(加工が切れない、AudioContext の中断、サンプルレートの不一致)を前提に、検出して信頼度フラグか録り直しで扱う。

## 9. テストと検証計画

- **音声処理の単体テスト**: 既知の合成音で検証する(200 Hz の正弦波、倍音とノイズの混合、ジッターとノイズを制御した信号)。
- **Parselmouth との回帰テスト**: 合成信号と実録音20〜50本で、F0、HNR、CPPS の差を測る。許容差の初期案は、F0の中央値 ±1 Hz、HNR ±1.5 dB、CPPS ±0.5 dB、相関 r>0.95(出典のない初期案)。
- **判定のテスト**: 合成した特徴量から、各タイプと中間タイプに期待どおり分類されることを確認する。
- **画面の通し確認**: Playwright と Chromium の疑似マイク機能に WAV を流す。
- **実機確認**: iPhone Safari と Android Chrome で手動確認する。ブラウザ録音と Praat を比較した研究は見つかっていないため、複数機種での自前測定が妥当性を担保する唯一の手段になる。
- **β運用での検証**: 日本語話者の性別別パーセンタイル表の作成、タイプの再現率(再測定の一致率)、聴取者の評定との相関を測る。再現率が低ければ、タイプ数を減らす。

## 10. プライバシーと法務

- 音声、特徴量、スコアはブラウザ内のみで扱う。話者識別用のテンプレートは作らない。アクセス解析、エラーログ、URL、共有画像、外部APIに、音声由来の値を渡さない。履歴機能は v1 に入れない(将来入れる場合も、保存は端末内で、既定は保存なし)。
- 画面には「当社のサーバーには送信しません」と、技術的事実で書く。「個人情報を取得しない」とは断言しない。文言と実装の一致を、リリースごとに確認する。
- 16歳未満は保護者と一緒に使うよう案内する。年齢の自己申告ゲートを置く。
- マイク権限は、利用者の操作後に、事前説明、ブラウザの許可の順で求める。録音中は表示を出し、停止と破棄を即時に行う。
- 免責は補助であり、非該当は、機能と表示の実質で担保する。
- **リリース前に弁護士とPMDA総合相談で確認する事項**: 該当性、名称への「診断」の可否(本設計は「声のタイプチェック」を仮称とする)、受診案内の表示と期間、景品表示法と健康増進法、個人識別符号への該当性、解析ツールの第三者提供と越境移転、改正個人情報保護法の施行日。

## 11. 根拠の質と既知の限界

- 調査の根拠の大半は、検索の要約である。論文の本文は読めておらず、官公庁サイト(PMDA、厚労省、個人情報保護委員会、e-Gov)も確認できていない。法務の記述は調査メモであり、法的助言ではない。
- 日本語話者の CPPS の基準値、読み上げの話速(mora/s)、F0の変動(半音)の基準値、alpha ratio、Hammarberg 指数、H1-H2 の基準値は取得できていない。
- 声タイプの軸(明るさ×澄み具合)を直接検証した研究はない。日本の商用の声タイプ診断と同型であるという状況証拠にとどまる。
- 品質ゲートの値、段階目標の数値、境界値、許容差は、出典のない暫定値で、実機データで較正する。
- 端末とマイク、録音環境で数値はぶれる。日内変動もある。
- 自動テストでは、実際の声に対する判定の妥当性は保証できない。
- QTV Academy の独自理論と、プロの声解析士による内容確認は含まない。

## 14. 実装後の変更点(Amendments、2026-11-09)

実装とレビューの過程で、設計書の記述から次のように変えた。理由は括弧内。

- **録音の流れ**: 母音の録音は約6.5秒(画面の案内は「約5秒」、「あと N 秒」のカウントダウン付き)。母音のあとに1.5秒の休み(「ひと息ついてください」)を入れ、そのあと文の読み上げを始める。各録音の最初の200 ミリ秒は捨ててから、0.5秒の無音区間(ノイズの基準)を取る。(母音の余韻や、話し始めが遅い人が、誤って「周りの音が大きい」「母音が短い」と判定されるのを防ぐため)
- **録音準備中の表示**: 準備中(約0.7秒)は、読み上げ文や母音の案内を隠し、「準備しています。静かにお待ちください」だけを表示する。(準備中に話し始めると、無音区間に声が入るため)
- **マイクの扱い**: 結果画面、録り直し画面、エラー画面では、マイクを閉じる。「もう1セット録音する」「もう一度録音する」を押したときに、マイクを開き直す。結果画面と録り直し画面に「最初にもどる」ボタンを置く。
- **解析中の表示**: 「終了」を押したあと、「結果をまとめています…」を表示してから解析する(解析は引き続きメインスレッドで行う)。
- **結果画面の追加**: 2セット目以降は「より安定した結果」を表示する。端末の音声処理が有効だった場合と、周囲の音がやや大きかった場合は、中立的な言葉で注意書きを表示する(第6節・第7節の「処理あり・信頼度低」の旗に当たる)。「測った値」として、声の高さ(Hz と音名)と、母音の安定(セント)を表示する。**話す速さの値は表示しない**(設計書は「本人比」としているが、v1 には保存された基準がないため。フィードバックの選択にだけ使う)。練習の頻度の案内(週3〜5日、2〜4週)を表示する。
- **ホスティング**: Vite の `base` を `./` にした。静的サイトを、サブパス(GitHub Pages の `/リポジトリ名/` など)に置いても動く。
- **CPPS**: Praat(Parselmouth)と、合成した声32〜36本で照合し、計算を Praat に合わせた。ノイズなしの純音では、Praat との差が最大約0.9 dB(300 Hz では約3.6 dB)ある。実際の録音での検証は、まだ行っていない。
- **既知の未解決点**: 声の高さの検出で、ノイズが大きい(SNR約8 dB)16 kHz の録音で、1オクターブ低く出る例がある(品質ゲートが先に録り直しにする)。実機(iPhone、Android)での確認と、実際の録音データでの基準値の作成は、まだ。
- **SNR の基準の緩和**: 実機(MacBook、静かな部屋)で毎回「周りの音が大きい」と判定される報告があった。マイクの直流分や低周波のごろごろ音、発声区間に含まれる間やブレスが原因と考え、SNR の計算に直流除去と 80 Hz のハイパス、20 dB の発声窓を加え、再録音の基準を 25 dB から 20 dB に下げた。基準値は仮で、実際の録音で調整する。再録音の画面には測定値の目安を小さく表示する。。なお、SNR の計算方法も変えた(直流分と 80 Hz 未満を除き、発声区間は最も大きいフレームから 20 dB 以内だけで測る)ため、新しい値は初版の値と直接は比べられない。実質的には、初版の「25 dB」より、文の録音で約10 dB ゆるくなる見込み。ノイズフロアの警告(-50 dBFS)も、高域通過後の値で判定する
- **読み上げ文**: 「北風と太陽」を知らない利用者がいたため、「桃太郎」の冒頭(61モーラ)に変えた。文の録音の上限は、ゆっくり読む人のために 12 秒から 15 秒にした。
