# 実機チェックリスト(iPhone Safari / Android Chrome)

自動テスト(Vitest、Playwright の偽マイク)では確かめられない項目を、実機で手で確認する。
端末ごとに、このファイルをコピーして記入する。数値の妥当性は、合成音でしか Praat と照合していない
(`tests/golden`)。実機の録音で何か気づいたら、備考に書く。

準備: HTTPS で配信したビルド(`npm run build` の `dist/`)の URL。静かな部屋と、うるさい部屋(テレビや換気扇など)。

## 1. 起動と許可
- [ ] HTTPS の URL が開く(アドレスバーに警告が出ない)
- [ ] 録音開始でマイク許可のダイアログが出る
- [ ] 「許可しない」を選ぶと説明画面(「マイクが許可されていません」)が出て、開始画面に戻れる
- [ ] 設定からマイクを許可し直すと、最初から通しで録音できる
- [ ] 許可した後の流れ(母音 → 1.5 秒の休み → 文章 → 結果)が止まらずに進む

## 2. 音声の加工が切れているか
アプリに `?debug` 表示は無い。リモートインスペクタで確かめる。
- iPhone: Mac の Safari →「開発」メニュー → 端末名 → 対象ページ
- Android: PC の Chrome で `chrome://inspect` → 対象ページの「inspect」

コンソールで次を実行し、出力をそのまま表に貼る:
```js
navigator.mediaDevices.getUserMedia({ audio: true }).then((s) => s.getAudioTracks()[0].getSettings())
```
- [ ] `echoCancellation` が false
- [ ] `noiseSuppression` が false
- [ ] `autoGainControl` が false(項目が無い場合は「無し」と書く)
- [ ] `new AudioContext().sampleRate` の値(44100 か 48000 か)を書き留めた

## 3. 録音中の中断
- [ ] 録音中に画面を消す → 録音は破棄され、「録音が中断されました」が出る
- [ ] 録音中に別のアプリへ切り替えて戻る → 同じく破棄され、「録音が中断されました」が出る
- [ ] 録音中に電話の着信(または通知音、アラーム)→ 何が起きたかを書く(破棄されるか、結果が出てしまうか)
- [ ] 中断の後、もう一度録音すると正常に進む

## 4. マイクと環境
- [ ] Bluetooth イヤホンのマイクで録音 → 何が起きたかを書く(狭帯域になり、警告が出るか、値が大きく変わるか)
- [ ] うるさい部屋 → 「周りの音が大きいようです。…」が出て、結果に進まない
- [ ] 静かな部屋 → 警告なしで結果まで進む
- [ ] 口からマイクまで 15〜30 cm で、音量の警告が出ない
- [ ] 極端に近い(5 cm 以下)→「音が大きすぎて割れていました。…」、遠い(1 m 以上)→「声が小さく録音されました。…」が出るか書く

## 5. 使い勝手
- [ ] 母音と文章の間の 1.5 秒の休みが、短すぎず長すぎない
- [ ] 3 セットを続けて録音できる(途中で固まらない、端末が熱くならない)
- [ ] 結果画面が 360 px 幅で横にはみ出さない
- [ ] 端末の文字サイズを最大にしても、結果画面と凡例の注記が読める
- [ ] 固定フッター(中止の案内)が常に見えていて、ボタンや本文に重ならない

## 6. オフライン
- [ ] 一度読み込んだ後に機内モードにしても、録音から結果まで動く(アプリは通信を使わない)
- [ ] 機内モードでページを再読み込みしたときの挙動を書く(キャッシュが無ければ開けないのは想定どおり)
